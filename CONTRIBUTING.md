# Contributing to IATF

This is the org-wide default. Each active repository has its own
`CONTRIBUTING.md` with repo-specific setup. If a repo doesn't have one,
the guidance below applies.

## Where to start

- **Found an accessibility barrier on `iatf.cc`?** Email
  <accessibility@iatf.cc>. Site barriers are reviewed there first;
  IATF maintainers move them into the relevant repository after
  redaction when needed. See <https://iatf.cc/accessibility/>.
- **Found an accessibility issue in a specific IATF project?** Open
  an issue on that project's repository, using the "Accessibility
  barrier" issue template.
- **Have a real accessibility need that could become a project?** Send a
  request through <https://iatf.cc/propose/>.
- **Want to contribute code, docs, or translations to an existing
  project?** Open an issue or PR on the relevant repo. Read its README
  first to understand scope and current status.

## Working in IATF repos

- Keep changes focused. One concern per PR.
- Default to plain language in commits, issues, and PR descriptions.
  This is an accessibility project; clarity is part of the work.
- Respect privacy. Do not include private contact details, medical
  information, or identifying information about individual users of
  assistive technologies in public issues, PRs, or commits.
- Follow each repo's existing conventions for commit messages, branch
  naming, and tests.

## Asking for help

- Email: <contact@iatf.cc>
- Discord: <https://iatf.cc/discord>

## Code of conduct and security

All contributors are expected to follow the
[Code of Conduct](./CODE_OF_CONDUCT.md). Vulnerabilities go through
[SECURITY.md](./SECURITY.md), not public issues.
